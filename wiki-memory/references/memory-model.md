# 记忆模型、页面写法与迁移

## 为 vibecoding 调整的边界

保留原体系的当前状态、决策、知识、事件日志及来源关系；按用户指定模式和实际恢复负担控制维护成本。小项目可一页状态；用户明确指定 standard 时必须完成五页的实质内容。已核实事实随任务同步，未决选择仍需确认；日志只为持久价值而写。原始资料无需整包复制，理念长文、空分类目录和模板不会常驻启动上下文。

记忆支持模型恢复上下文，不能保证模型绝不遗忘，也不代替代码验证、测试或用户授权。通过根指令接入可让后续会话找到协议，不能靠 Skill 的自动触发保证每次任务维护。

可选理论背景见 [llm-wiki 原文](llm-wiki.md)。所链接的 `llm-wiki.md` 于 2026-10-09 从用户提供的本地模板 `C:/Users/Administrator/Desktop/工程记忆构建/wiki_memory/llm-wiki.md` 原样保留，SHA256 为 `b77049fe3d30704134098c12562c39aad3696f3a509c99031d16fc598fdb0866`；作者与上游 URL 未核实。原文帮助理解来源、专题与索引的关系，不要求每次任务阅读，也不将个人知识库、课堂笔记或原文中的写入行为纳入本 Skill 的工程维护范围或授权。

## 根目录与页面分工

新建与升级后的记忆根固定为 `<project-root>/wiki_memory/`。`docs/wiki_memory/` 等旧位置只支持只读盘点，不能以“文档统一放 docs”继续创建或维护新规范的记忆。先根据用户目标、仓库和工程配置确定项目根目录；不能为了通过路径限制把某个普通子目录冒充工程根。

顶层只保留一个导航说明 `README.md` 和一个维护协议 `AGENTS.md`，不另建 `入口.md`。README 说明模式、选择依据、必读路线和检索方式，链接当前状态与目录 MOC；不复制目标、技术状态和待办。AGENTS 保存核实、写入、授权、交接与工具规则，不重复导航表。中文专题文件和目录名保留。

standard 五页的必需章节见 [Skill 内容合同](../SKILL.md#standard-内容合同)。它们要能支持一次真实交接：另一位 Agent 应能定位实际入口，理解模块关系，知道正在做什么、下一步做什么以及哪些验证还缺失。仅有“待核实”“根据项目填写”等提示语不算完成；没有已知缺陷可以明确记录检查范围与残余验证缺口。存在未知项时给出其影响及核实方法，不把候选需求包装成问题。

重要结论就近连接代码、配置、正式文档或用户要求；页面末尾“证据与未核实项”汇总核实日期与范围。验证证据包括实际命令、结果、环境、已知 revision 及未提交变更背景。当前约束写明本项目的交付权限，不复制另一个项目的持续提交授权。Git 分支和工作区信息标注记录时点，接续时重查。

standard 不要求每个模块都建立知识页或 ADR；已有正式文档时引用它。已经采用的关键设计不能完全丢在日志中，应在架构页或对应决策页保存选择者、依据、取舍与实施状态。

## 日志分类与实物示例

standard 必须有六个日志分类目录，并按任务日志的 `kind` 归档。目录和用途沿用用户提供的 `工程记忆构建/wiki_memory/日志` 模板；lite 可以在 `日志/` 直接平铺，不必建立六类目录。

| kind | standard 目录 | 主要交付物 | 实际文件示例 |
| --- | --- | --- | --- |
| `feature` | `日志/功能添加/` | 新功能、行为变化与功能重构 | [添加导出功能](../assets/standard-log-layout/功能添加/2026-10-09-示例-添加任务导出.md) |
| `ui` | `日志/UI修改/` | 界面、外观与样式 | [调整按钮间距](../assets/standard-log-layout/UI修改/2026-10-09-示例-调整按钮间距.md) |
| `bug` | `日志/Bug处理/` | 异常诊断、恢复与修复 | [修复空列表报错](../assets/standard-log-layout/Bug处理/2026-10-09-示例-修复空列表报错.md) |
| `discussion` | `日志/工程讨论/` | 有持久价值的方案比较、架构讨论与计划 | [比较缓存方案](../assets/standard-log-layout/工程讨论/2026-10-09-示例-比较缓存方案.md) |
| `test` | `日志/测试验证/` | 独立的测试、审查、检查或验收 | [验证导出行为](../assets/standard-log-layout/测试验证/2026-10-09-示例-验证导出行为.md) |
| `maintenance` | `日志/工程维护/` | 文档、配置、依赖、清理与迁移 | [整理运行说明](../assets/standard-log-layout/工程维护/2026-10-09-示例-整理运行说明.md) |

[assets/standard-log-layout/](../assets/standard-log-layout/) 是可以直接浏览的六目录结构，每类放一篇明确标注为虚构教学内容的日志。它用于理解目录与 `kind` 的对应关系；样例项目、任务结果与验证均不是事实，不作为真实来源，不复制进目标工程。初始化只为 standard 建立六类目录和 `.gitkeep`，无任务时保持空目录，不制造历史。

每个任务按主要交付物选择一个 `kind`。添加功能时的测试仍写在 feature 日志里，不为步骤拆出多份记录；只读讨论不因为有 discussion 目录就获得写入授权。standard 每篇日志必须有合法 `kind` 并位于对应目录，不能在日志根平铺或以其他分类名替代这六类。

两种模式都保留单一 `日志/MOC_工作日志.md`，跨目录按时间和类型汇总；分类目录里不维护子 MOC、README 或第二套导航。检索时先按主题定位，需要历史再按类型或关键词搜索；文件夹分类不替代当前状态、决策或知识页。

文件名使用 `YYYY-MM-DD-短标题.md`，同目录同名追加 `-02`、`-03` 等编号，独占创建以免并行覆盖。普通 Markdown 链接随所在目录相对解析；记忆内部 Wiki 链接使用从记忆根算起的完整路径。新增子目录后需多一层 `../` 的链接要核实，不能照抄旧平铺文件里的相对路径。

## 页面写法

最小状态 / 知识页：

```yaml
---
type: knowledge
status: active
updated: 2026-10-07
topic: checkout-validation
sources:
  - "src/checkout/validate.ts"
  - "tests/checkout.test.ts"
---
```

正文写适用模块、一句话结论、证据与限制。实际使用时换成真实日期和路径；仅有配置而未执行的测试明确标注。页面跨多个事实时，正文每个重要结论附对应来源，避免一组文件给所有推断背书。创建空架子用 `status: proposed`，核实后才转有效。

区分三种容易混淆的内容：用户想要的产品行为、已经选定的方案、源码实际实现的行为。批准使用队列不等于队列已落地；源码临时绕开队列不等于用户批准改变架构。将差异列为待处理事项，不能用事实自动同步替代决策确认。

`updated` 是编辑日期，不是“本页所有结论仍正确”的保证。可选 `verified` 表示整页当前关键事实整体复核过的日期；局部复核在相应结论旁记录日期和范围，不抬高其余结论的可信度。旧版本没有 `verified` 时工具只能按编辑年龄提示，不能推断真实核实时间。

任务日志除公共字段外，可写：

```yaml
type: log
status: archived
kind: bug
task_status: blocked
updated: 2026-10-07
topic: checkout-timeout
sources: ["src/checkout/client.ts"]
```

正文简述目标、完成范围、实际验证、未完成项、恢复命令或下一步。`archived` 是页面性质，不能用它推断任务成功。用户只要求检索、体检或只读审查时不生成任务日志。

测试结果注明实际命令、环境、结果、验证范围和已知的 Git revision；有未提交变更时明确记录“包含本地变更”，不能把它说成某个已提交版本通过。历史源码路径后续可能删除，日志仍保持原记录；用当时 revision 或关联决策追溯，不为消除体检提示重写历史。

决策页用 `ADR-NNN-标题.md`，先查看现有编号。正文保留背景、选择、理由、代价、适用范围、验证线索与授权依据。用户已指定的选择可直接记 active；Agent 在已授权范围内已采用的常规实现选择也可记 active，但写清由 Agent 作出，不能声称用户确认。尚在比较或需要用户作出决定的方案记 proposed。有效决策表示“已经选定”，是否已实现仍需独立说明。

替代关系示例：

```yaml
type: decision
status: active
updated: 2026-10-07
topic: persistence
supersedes: "[[决策/ADR-001-local-storage]]"
sources:
  - "用户指令：2026-10-07 明确选用 SQLite"
  - "src/storage/sqlite.ts"
```

旧决策改 `superseded` 并链接新页。不要仅按日期较新就决定谁有效。没有确认依据时保留旧有效页，将新方案记候选。

必填字段为 `type/status/updated/topic`。保留原体系的 `importance/kind/source_logs/supersedes` 不会报错，但不要求每页填空字段。工具的 YAML 子集仅支持单行标量、双引号 JSON 列表和缩进字符串列表，字段重复或复杂语法报错；人工使用更完整 YAML 时不要宣称该工具支持。

## 检索与可信度

1. 先读 README 和当前状态，确定主题与模块路径。
2. 搜索该主题的 active 决策及知识页；命中很多时缩小到受影响模块。
3. 需要解释来由、复现旧问题或定位回归时，读日志 MOC，再取有关日志。日志索引增长后用 `rg` 搜索，不必通读整张表。
4. 回答中区分当前已核实、历史记录、候选和未知。存在冲突时同时指出两侧证据，不能把历史修复结论当成当前验证。

失效信号包括来源文件删除、模块重构、依赖或部署方式变化、切换分支、测试行为冲突、用户改动目标。当前有效页的来源缺失报错；封存日志、废弃知识或已替代决策的源码来源缺失作为历史追溯提示，记忆内部引用目标仍应保留。外部 URL 和用户声明需要人工核对。

## 迁移已有体系

- Git 项目若本任务包含提交 / 推送，先核对 upstream 的实际远程引用；`git status` 中的跟踪分支只是本地缓存。远程领先或分叉时，保全本任务与其他任务的改动，按项目授权整合后重新盘点记忆；不要先建立另一份再覆盖合并。没有远程或只做离线配置时，明确未核对远程，仍可完成本地工作。工具本身不联网、不执行 Git 同步。
- 先读取现有协议和导航，识别当前状态与已确认决策；不要重新运行 init。旧体系要求全部长期变更确认时先沿用；只有本次明确授权升级该策略才改为事实 / 决策分流。只修改 Skill 时，不顺便迁移其他项目。
- 先用本 Skill 脚本对旧目录只读盘点：`check --project "<root>" --memory-dir "<old-relative-dir>"`。`source_logs`、Obsidian 链接和 ADR 文件名继续支持。旧版 schema、旧位置或五页文件存在都不证明 standard 已完成，仍需逐页核对内容合同。
- 显式迁移时，保留已有主题、正文、日期、有效状态、来源与历史；迁移位置、日志分类和导航名称属于结构升级，不受“保留旧资料”约束。先确认目标根目录没有第二份有效记忆，核对实际路径在项目内，再将旧记忆迁到根目录 `wiki_memory/`。修正根指令、正文链接和 `sources` 等来源引用；引用位置变更可以最小修改历史页的路径，但不改写历史结论、日期、当时命令或任务结果。
- standard 平铺日志、旧自定义分类以及 lite 升级 standard 都要显式整理到六类目录。先盘点每篇日志的 `kind` 与主要交付物；缺字段时依实际记录补齐，不因文件名或预期结果猜测类型。移动前检查目标冲突，不能覆盖同名历史；移动后修复正文相对链接、`source_logs`、`sources`、Wiki 链接和其他引用页，重名 Wiki 引用改成完整路径。保留日志原日期、正文结论和当时命令；只修正路径不表示当年的命令已经重新执行。
- 合并旧 README 与 `入口.md`：先逐项盘点两者的手写说明和链接，将导航与使用说明合并进新 README 的自动区之外；重复事实链接到唯一有效状态页，特殊项目说明不得丢失。去除独立入口页，重写所有指向它的有效引用与历史内部链接，不留下竞争导航。README 为 active MOC，协议仍是 AGENTS。
- 原 `工具/memory_lint.py` 不必删除。接入新工具时放到未占用的路径；如已有同名不同内容，先检查其用途再定名，不能覆盖。
- 原索引没有自动区标记时，`index` 拒绝写入。迁移时盘点手写内容，合并到 README 或对应目录 MOC 的自动区之外；纯生成区用唯一成对的 `<!-- wiki-memory:auto:start -->` / `<!-- wiki-memory:auto:end -->` 包住。工具使用固定导航名：`README.md`、`日志/MOC_工作日志.md`，以及存在相关页面时的 `决策/MOC_决策.md`、`知识/MOC_知识.md`。旧 `索引.md` 等名称必须显式合并并更新引用，不承诺任意旧索引名可直接写入，也不要求用户改源码常量。四层以外的分类可保留为内容层，但工具管理的导航与五页必须接通。
- 保留旧工具时，明确哪一个负责当前索引，更新根指令及有效流程中的维护命令；会整页重写索引的旧工具留作历史，不能与新工具交替使用。旧日志中的命令保持原样。
- 接入时将 `.memory.json` 升级为 `schema_version: 2`，填写 `navigation: "README.md"`、用户指定或已选 `mode` 及实际 `tool_version`（本版 `3.1.0`），保留其他适用定制字段。先完成迁移再预览索引；工具拒绝对旧路径、旧 schema 或未完成日志分类的 standard 执行 index，不能只改版本字段规避规范。运行 `check --require-ready` 后逐项人工验收内容合同，旧格式只读检查通过不等于新布局、内容和根指令已接通。
- 若旧协议要求每个新 MOC 保留 `kind` / `importance`，在配置中加入 `"moc_defaults": {"kind": "process", "importance": "high"}`。它仅为新建目录 MOC 补这两个字段，已有页面的字段及手写说明不被覆盖；其他自定义 Schema 仍需按项目规则检查，工具不从自然语言协议自动推断。
- 用最小差异更新生效的根指令引用，统一指向 `wiki_memory/AGENTS.md` 与 `wiki_memory/README.md`。若已有引用指向旧路径，修正原引用，不再追加竞争接入块。深层指令是否屏蔽记忆接入仍需人工检查。
- 普通 Markdown 引用按页的相对目录规范化；wiki 引用按记忆根目录解析。`../` 只允许到项目内部；源码和配置链接无需伪造 `.md` 后缀。元数据来源也要检查，不能只检查正文。
- 大规模迁移先盘点与预览，分批迁移并核对新增 / 遗留项。保留历史；不要把候选、占位页或旧测试结果自动升级为当前事实。

## 扩展与压缩

lite 的一页明显拥挤，或用户要求 standard 时，将架构、约束、任务和问题拆到五页并补齐内容合同，同时建立六类日志目录、按主要类型迁移已有日志并修复引用；更新 `.memory.json` 的 `mode` 与 README 手写说明，记录选择者和依据。配置只描述布局，不授权改事实。旧单页可改为仅含导航的 MOC 或保留为 superseded，清除搬走的重复有效结论；不再运行 init。协议中的初始模式是历史信息，以配置为准。

大型仓库使用一份全局概览与约束；按服务 / 模块创建 `知识/模块/<module>.md`，页内说明职责、边界、入口、依赖、验证方式、常见陷阱。模块知识已有正式文档时只链接并补充恢复上下文所需的差异，不复制整份手册。工具将知识与决策放入各自目录 MOC，README 链接当前状态和检索 MOC。全局事实不要散落到每个模块页；分类 MOC 仍很大时按路径或主题搜索，不通读。

压缩时列出待合并页和重复结论，核实来源与冲突；更新当前页、保留来源日志和旧决策，再刷新 README 和索引。候选无法确认时留 proposed。不要为省 token 删除历史或抹掉失败验证。

## 工具验证范围

`check` 的错误影响结构可信度；warning 是人工复核线索，默认不影响退出码。新 schema 中必需导航须为 active MOC，自动区必须成对且唯一；旧路径和旧 schema 保留只读盘点兼容。standard 缺六类目录、日志缺少 `kind` 或归类不匹配时，旧 schema、缺 `tool_version` 或版本低于 `3.1.0` 的普通 check 给迁移警告，`3.1.0` 及以上配置报错；非法 `kind` 值始终按元数据错误处理。`--require-ready` 与 index 对所有 standard 严格检查日志结构。

`check --require-ready` 同时要求所选模式必需状态页 active、具有非空 `sources` 或 `source_logs`，对应章节非空且未原样保留初始化提示语。它只检查可机械核对的前提，不证明正文充分、来源真实或每条结论有支持；必须继续人工验收。工具不会运行项目测试、访问外部 URL、判断架构取舍或扫描全部敏感信息。

`index` 验证元数据、所选模式的必需状态页和替代关系后生成索引；只写自动区与 MOC 的编辑日期，其余内容保留。日志表格使用按索引页相对位置解析的 Markdown 链接，转义标题中的表格符号，避免 Wiki 别名分隔符破坏列数。应用前检查读取过的页面、文件集合、配置（包括原先不存在的配置）与目标是否变化，用项目级排他锁协调本工具写入，再原子替换文件；异常时尽力回滚本次写入，若他人已修改则保留新内容并报告需要检查。进程被强制终止时可能留下锁及尚未完成的多文件更新，应检查后重新索引。它不保证任意外部编辑器之间的事务一致性，不提供语义修复，不替代直接状态页编辑时的协作约定。

配置中的 lite / standard 对应约定的中文状态页；迁移中重命名这些页时，同时适配协议与工具检查，不能只改文件名后继续宣称模式完整。初始化发布新文件使用文件系统的原子硬链接，已存在文件使用原子替换；不支持相应操作的文件系统会报错并回滚，可按协议手工接入，不降级成覆盖写入。

锁文件存在时停止并说明当前进程可能仍在运行；确认进程已停止且清理在本次授权范围内后才移除遗留锁，已有明确授权不重复询问，禁止仅因超时自动删锁。预览及 check 不创建锁。项目工具副本可用 `--version` 查看；旧工具没有该参数时视为未标记版本，不据此重新初始化。升级时保留协议、手写页面和本地工具定制，对比后替换相应部分，再做体检和索引检查。

维护本 Skill 的脚本时，运行 `python scripts/test_memory.py` 验证拒绝覆盖、路径边界、元数据来源、索引幂等及历史不变等行为，再运行 `skill-creator` 的 `quick_validate.py`。
