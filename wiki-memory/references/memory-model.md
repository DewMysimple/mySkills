# 记忆模型、页面写法与迁移

## 为 vibecoding 调整的边界

保留原体系的当前状态、决策、知识、事件日志及来源关系；改变的是默认维护成本：小项目一页状态，稳定专题按需生成；已核实事实随任务同步，未决选择仍需确认；日志只为持久价值而写。原始资料无需整包复制，理念长文、空分类目录和模板不会常驻项目启动上下文。

记忆支持模型恢复上下文，不能保证模型绝不遗忘，也不代替代码验证、测试或用户授权。通过根指令接入可让后续会话找到协议，不能靠 Skill 的自动触发保证每次任务维护。

## 页面写法

最小状态 / 知识页：

```yaml
---
type: knowledge
status: active
updated: 2026-10-07
topic: checkout-validation
sources:
  - "src/checkout/validate.ts"
  - "tests/checkout.test.ts"
---
```

正文写适用模块、一句话结论、证据与限制。实际使用时换成真实日期和路径；仅有配置而未执行的测试明确标注。页面跨多个事实时，正文每个重要结论附对应来源，避免一组文件给所有推断背书。创建空架子用 `status: proposed`，核实后才转有效。

区分三种容易混淆的内容：用户想要的产品行为、已经选定的方案、源码实际实现的行为。批准使用队列不等于队列已落地；源码临时绕开队列不等于用户批准改变架构。将差异列为待处理事项，不能用事实自动同步替代决策确认。

`updated` 是编辑日期，不是“本页所有结论仍正确”的保证。可选 `verified` 表示整页当前关键事实整体复核过的日期；局部复核在相应结论旁记录日期和范围，不抬高其余结论的可信度。旧版本没有 `verified` 时工具只能按编辑年龄提示，不能推断真实核实时间。

任务日志除公共字段外，可写：

```yaml
type: log
status: archived
kind: bug
task_status: blocked
updated: 2026-10-07
topic: checkout-timeout
sources: ["src/checkout/client.ts"]
```

正文简述目标、完成范围、实际验证、未完成项、恢复命令或下一步。`archived` 是页面性质，不能用它推断任务成功。用户只要求检索、体检或只读审查时不生成任务日志。

测试结果注明实际命令、环境、结果、验证范围和已知的 Git revision；有未提交变更时明确记录“包含本地变更”，不能把它说成某个已提交版本通过。历史源码路径后续可能删除，日志仍保持原记录；用当时 revision 或关联决策追溯，不为消除体检提示重写历史。

决策页用 `ADR-NNN-标题.md`，先查看现有编号。正文保留背景、选择、理由、代价、适用范围、验证线索与授权依据。用户已指定的选择可直接记 active；Agent 在已授权范围内已采用的常规实现选择也可记 active，但写清由 Agent 作出，不能声称用户确认。尚在比较或需要用户作出决定的方案记 proposed。有效决策表示“已经选定”，是否已实现仍需独立说明。

替代关系示例：

```yaml
type: decision
status: active
updated: 2026-10-07
topic: persistence
supersedes: "[[决策/ADR-001-local-storage]]"
sources:
  - "用户指令：2026-10-07 明确选用 SQLite"
  - "src/storage/sqlite.ts"
```

旧决策改 `superseded` 并链接新页。不要仅按日期较新就决定谁有效。没有确认依据时保留旧有效页，将新方案记候选。

必填字段为 `type/status/updated/topic`。保留原体系的 `importance/kind/source_logs/supersedes` 不会报错，但不要求每页填空字段。工具的 YAML 子集仅支持单行标量、双引号 JSON 列表和缩进字符串列表，字段重复或复杂语法报错；人工使用更完整 YAML 时不要宣称该工具支持。

## 检索与可信度

1. 先读入口和当前状态，确定主题与模块路径。
2. 搜索该主题的 active 决策及知识页；命中很多时缩小到受影响模块。
3. 需要解释来由、复现旧问题或定位回归时，读日志 MOC，再取有关日志。日志索引增长后用 `rg` 搜索，不必通读整张表。
4. 回答中区分当前已核实、历史记录、候选和未知。存在冲突时同时指出两侧证据，不能把历史修复结论当成当前验证。

失效信号包括来源文件删除、模块重构、依赖或部署方式变化、切换分支、测试行为冲突、用户改动目标。当前有效页的来源缺失报错；封存日志、废弃知识或已替代决策的源码来源缺失作为历史追溯提示，记忆内部引用目标仍应保留。外部 URL 和用户声明需要人工核对。

## 迁移已有体系

- Git 项目若本任务包含提交 / 推送，先核对 upstream 的实际远程引用；`git status` 中的跟踪分支只是本地缓存。远程领先或分叉时，保全本任务与其他任务的改动，按项目授权整合后重新盘点记忆；不要先建立另一份再覆盖合并。没有远程或只做离线配置时，明确未核对远程，仍可完成本地工作。工具本身不联网、不执行 Git 同步。
- 先读取现有协议和入口，识别哪一页代表当前状态、哪些决策已确认；不要重新运行 init。旧体系要求全部长期变更确认时，先沿用。只有用户本次明确授权升级该策略，才改为本 Skill 的事实 / 决策分流。
- 保留原目录、日期、话题、有效状态和来源链接。用户本次指定的是创建 Skill 时，不顺便修改桌面的原始 `wiki_memory`。
- 原中文五页布局可直接视为 standard。原 `source_logs`、Obsidian 链接和 ADR 文件名继续支持。先用本 Skill 脚本对旧目录执行只读 `check --project "<root>" --memory-dir "<relative-dir>"`。
- 原 `工具/memory_lint.py` 不必删除。接入新工具时放到未占用的路径；如已有同名不同内容，先检查其用途再定名，不能覆盖。
- 原索引没有自动区标记时，`index` 会拒绝写入。要迁移，先检查用户手写内容，手动把纯生成区包进 `<!-- wiki-memory:auto:start -->` 和 `<!-- wiki-memory:auto:end -->`，其余内容保留在区外；先建立缺少的统一入口。保留原索引路径；不要求用户编辑工具源码常量来完成常规迁移。若现有目录名称与工具支持的四层不同，继续使用现有工具并手工维护索引，不宣称它已兼容此工具。
- 保留旧工具时，明确哪一个负责当前索引，更新根指令及有效流程中的维护命令；会整页重写索引的旧工具留作历史，不能与新工具交替使用。旧日志中的命令保持原样。
- 接入时补齐 `.memory.json` 的 `schema_version: 1`、所选 `mode` 和实际 `tool_version`，再预览索引并体检。旧格式只读检查通过不等于新布局的入口、导航标记、必填页和根指令已接通。
- 若旧协议要求每个新 MOC 保留 `kind` / `importance`，在配置中加入 `"moc_defaults": {"kind": "process", "importance": "high"}`。它仅为新建目录 MOC 补这两个字段，已有页面的字段及手写说明不被覆盖；其他自定义 Schema 仍需按项目规则检查，工具不从自然语言协议自动推断。
- 用最小差异更新生效的根指令入口。若旧入口指定另一记忆路径，修正原入口，禁止再追加一个竞争入口。深层指令是否屏蔽入口需要人工检查。
- 普通 Markdown 引用按页的相对目录规范化；wiki 引用按记忆根目录解析。`../` 只允许到项目内部；源码和配置链接无需伪造 `.md` 后缀。元数据来源也要检查，不能只检查正文。
- 大规模迁移先盘点与预览，分批迁移并核对新增 / 遗留项。保留历史；不要把候选、占位页或旧测试结果自动升级为当前事实。

## 扩展与压缩

lite 的一页明显拥挤时，手动将架构、约束、任务、问题拆到 standard 的主题页，更新 `.memory.json` 的 `mode` 和入口手写说明，记录扩展理由。该配置只描述布局，不授权改事实；工具索引会发现新页。旧单页改为仅含导航的 MOC 或保留为 superseded，清除已搬走的重复有效结论；不再运行 init。协议中的初始模式是历史信息，以配置为准。

大型仓库使用一份全局概览与约束；按服务 / 模块创建 `知识/模块/<module>.md`，页内说明职责、边界、入口、依赖、验证方式、常见陷阱。模块知识已有正式文档时只链接并补充恢复上下文所需的差异，不复制整份手册。工具将知识与决策放入各自目录 MOC，入口只保留当前状态和这些检索入口。全局事实不要散落到每个模块页；分类 MOC 仍很大时按路径或主题搜索，不通读。

压缩时列出待合并页和重复结论，核实来源与冲突；更新当前页、保留来源日志和旧决策，再刷新入口。候选无法确认时留 proposed。不要为省 token 删除历史或抹掉失败验证。

## 工具验证范围

`check` 的错误影响结构可信度；warning 是人工复核线索，默认不影响退出码。配置了 `.memory.json` 时，必需导航须为 active MOC，自动区必须成对且唯一；未配置的旧格式保留只读兼容，不强加生成标记。新建空模板会提示尚无有效当前状态，不能把“工具退出码为零”理解成初始化事实已完成。工具不会运行项目测试、访问外部 URL、判断架构取舍或扫描全部敏感信息。

`index` 验证元数据、所选模式的必需状态页和替代关系后生成索引；只写自动区与 MOC 的编辑日期，其余内容保留。日志表格使用按索引页相对位置解析的 Markdown 链接，转义标题中的表格符号，避免 Wiki 别名分隔符破坏列数。应用前检查读取过的页面、文件集合、配置（包括原先不存在的配置）与目标是否变化，用项目级排他锁协调本工具写入，再原子替换文件；异常时尽力回滚本次写入，若他人已修改则保留新内容并报告需要检查。进程被强制终止时可能留下锁及尚未完成的多文件更新，应检查后重新索引。它不保证任意外部编辑器之间的事务一致性，不提供语义修复，不替代直接状态页编辑时的协作约定。

配置中的 lite / standard 对应约定的中文状态页；迁移中重命名这些页时，同时适配协议与工具检查，不能只改文件名后继续宣称模式完整。初始化发布新文件使用文件系统的原子硬链接，已存在文件使用原子替换；不支持相应操作的文件系统会报错并回滚，可按协议手工接入，不降级成覆盖写入。

锁文件存在时停止并说明当前进程可能仍在运行；确认进程已停止且清理在本次授权范围内后才移除遗留锁，已有明确授权不重复询问，禁止仅因超时自动删锁。预览及 check 不创建锁。项目工具副本可用 `--version` 查看；旧工具没有该参数时视为未标记版本，不据此重新初始化。升级时保留协议、手写页面和本地工具定制，对比后替换相应部分，再做体检和索引检查。

维护本 Skill 的脚本时，运行 `python scripts/test_memory.py` 验证拒绝覆盖、路径边界、元数据来源、索引幂等及历史不变等行为，再运行 `skill-creator` 的 `quick_validate.py`。
