# 隔离换会话评测

维护本 Skill 的读取、事实核实或迁移行为时使用；普通项目任务不自动运行。脚本单测验证机械行为，本评测另外观察新会话能否找到入口、恢复下一步和识别过期记忆。

## 建立案例

```text
python "<skill-dir>/scripts/handoff_cases.py" --date 2026-10-10
```

需要 Git 与 Python 3.10+，不调用网络或模型 API。默认在系统临时目录新建四个独立工程，打印各工程路径与用户请求；--output 只能指定尚不存在的目录，不覆盖已有材料。案例有实际源码、配置、测试、Git 历史和已接入的 lite 记忆；基线测试真实执行后才写入结果。所有内容是虚构评测材料，不进入真实工程历史。案例包括中断接续、源码冲突、切换分支和 lite 升级 standard。

## 新会话执行

为每个案例建立无历史上下文的独立评测 Agent，提供用户请求、项目路径及必要材料；明确的升级任务再给 Skill 路径，普通接续 / 只读案例不要求调用 Skill。评测 Agent 只访问该临时工程及实际需要的 Skill 包；前三项只读，升级项只允许修改自己的临时工程。不要提供预期答案、疑点或评分规则。没有独立 Agent 时可由用户在新会话执行，记录实际限制，不把同一会话自查称为独立验证。

## 评审实际结果

评测结束后检查其报告、工具调用和产物：

- 是否通过根指令 → 协议 / README → 必读状态找到具体源码、配置与测试入口。
- 接续任务是否指出已完成与未完成范围，以及可执行的文件和命令。
- 是否依据源码说明当前事实，指出冲突但不把漂移确认为新决策。
- 是否重查分支、revision 与本地变更，限制历史测试结论的适用范围。
- 升级是否填好五页实质状态、保留历史正文 / 日期 / 当时命令、修正路径与日志分类，并实际通过 check --require-ready。
- 启动必读字符量、额外读取文件、无关页数及实际字符量；字符数不换算为 token。同一文件重复读取另记，避免只看文件数。

保存简短的实际结果、失败点及验证范围。一次通过只证明该案例与当时版本的表现；其他平台和真实大型工程仍须按实际情况核实。需要修复时只针对观察到的问题，不按单个案例增加通用限制。
