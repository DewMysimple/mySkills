# 转录编辑回归评审

- [cases.json](cases.json) 保留 13 组通用回归，包含字面标记、文件边界、纠错和排版行为。
- [practice-cases.json](practice-cases.json) 提供 14 组真实问题的去身份化最小复现。E1–E4 检查安全修复有没有发生，E5–E9 检查歧义、修正链、推测和数字保护，S1–S5 检查主题导航与列表取舍。

每条记录的 `source` 可以直接保存为 UTF-8 Markdown 输入，`good` 是一份合格候选，`bad` 至少有一处明确问题。`fidelity` 和 `readability` 分别记录两类判据。候选可以采用不同措辞和段落，评审依据来自原文与判据。

## 运行

1. 在临时目录为每个样例保存一份独立的 `source.md`，保留原始换行。用同一个请求调用待测 Skill，例如「请用这个 Skill 把 source.md 整理成便于查找和复习的 Markdown 课堂实录」。运行端只接触对应的 Skill 和输入。预期候选与判据留给评审端。
2. 对比修改前后时，分别使用两个版本的完整 Skill，在隔离会话中运行同一份输入，固定模型、推理设置和工具权限。核对实际加载的 `SKILL.md` 路径和 SHA-256，以免把已安装副本当作待测版本。记录实际模型、运行范围、是否完成及输出路径。评审时用匿名标签区分候选。
3. 检查源文件未改动、正式产物在预期位置，逐项核对两类判据。记录样例集、ID、两个维度各自的通过情况、有关原文与候选片段。任何未运行或未能判定的项目保留该状态。

运行环境只允许返回正文时，可以用 CLI 收集 Markdown 继续做内容对照，文件写入和默认路径另行验证。

## 判定

| 维度 | 通过条件 | 失败证据示例 |
| --- | --- | --- |
| 保真 | 内容、推理、顺序与原文可逐项对应，关键字面数据及文档边界完整，有依据的 ASR 修复与模棱两可的原样保留都得到验证 | 删去自我修正、扩大结论适用范围、添加原文没有的定义、改变标识符 |
| 可读性 | 纯噪声和断裂句得到处理，段落体现语义单元，标题和列表符合原话结构，讲者的表达仍可辨认 | 单一论证被多个标题拆开、原有自然过渡淹没在连续大段中、一个句子仍散落在几个段落 |

保真与可读性分开判断。字符差异和自动检查提示只用于定位复核点。先核对 `good` 在两个维度均合格，并记录 `bad` 至少一个可定位的失败点，再将相同判据用于新候选。E1–E3 和 S1 的反例原样保留输入，用于识别错过的修复或导航机会。整理失败或正式产物缺失也应记录。

在仓库根目录运行字面检查器的单元测试。

```powershell
python -X utf8 -B -m unittest discover -s video-transcript-polisher/tests -v
```

单元测试覆盖字面信号。候选的保真和可读性仍按上表逐项评审。

小样例用于比较编辑判断。检查分段降级时，可在同一文件内按主题串联多个合成片段，把同一个术语、带条件的推测与后续自我修正放在相邻边界两侧。在隔离会话中限制单次读取的源行数，模拟容量受限。核查范围账本是否连续覆盖全文、术语是否一致、边界是否重复或漏写、源文件哈希和元数据是否保持，以及未完成时是否报告范围并保留正式目标。

## 文件流程回归

在隔离目录中使用合成 Markdown，以普通用户请求给出源路径、目标路径和授权范围。每次只发一次请求。记录模型、权限、委派功能是否可用、实际读取的 Skill 路径和指纹、运行轨迹及最终文件。以下判据留给评审端。

| 场景 | 文件与轨迹判据 |
| --- | --- |
| 十份无 frontmatter 原稿，输出到空 `Test/`，源不改 | 十份输出都在指定目录，正文从首行开始，源文件哈希相同，预检后直接处理 |
| 同一请求中一份目标已存在，覆盖未获授权 | 其余九份保存，已有目标字节保持，报告冲突路径和结果 |
| 两份原稿映射到同一目标，另有一份独立输入 | 冲突目标不写入，独立输出正常保存，各输出只包含对应原稿内容 |
| 用户明确要求全部成功才提交，有一项冲突 | 正式目标均保持原状，报告阻止发布的原因 |
| 两份已批准正文分别回填到两个明确授权的目标 | 有效目标的 BOM、CRLF 和 frontmatter 前缀保持原字节，正文只调整开头分隔空行；缺少闭合边界的目标保持原状 |

核对写入轨迹中两个审查都早于正式发布。检查发布操作会拒绝覆盖预检后才出现的目标。单独验证此属性时，可以让两个暂存候选同时发布到同一路径，核对只有一个成功且胜出的字节保持原样。

原生委派可用和不可用时均用同一结果契约验收。若要验证实际委派，检查运行轨迹中的派发与返回事件。发布说明前核对运行器发现的 Skill 副本，例如查看桌面端所用 app server 的 `skills/list` 结果和实际 Skill 读取轨迹。区分目录中存在的副本、被发现的路径与该次任务真正读取的路径。改用新会话加载待验证版本，并比对入口与参考文件的 SHA-256。
