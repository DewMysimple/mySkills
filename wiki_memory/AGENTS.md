# 工程 Agent 记忆维护协议

本文件是 mySkills 工程记忆的 Schema 层。它规定 Agent 如何读取、写入、压缩和检查 wiki_memory/，但不替代仓库根目录的 AGENTS.md。

## 记忆模型

- 当前状态/：当前仍然有效的项目事实，每个主题只保留一个 active 版本。
- 决策/：会影响后续维护方式的架构、范围和工程决策。
- 知识/：稳定的模块说明、流程、规范和运维知识。
- 日志/：一次实质任务的追加式历史记录，不作为当前事实的唯一来源。
- AGENTS.md：记忆系统自身的维护协议。

原始代码、Skill 文件、配置和用户要求仍是事实来源。记忆只记录结论、关系、来源和相对路径，不复制大段原文。

## 会话开始时的读取顺序

1. 读取本文件和仓库根目录 AGENTS.md。
2. 读取 当前状态/项目概览.md、当前状态/系统架构.md、当前状态/当前约束.md、当前状态/当前待办.md。
3. 读取与当前任务相关的 active 决策和知识页。
4. 只有需要追溯时才读取最近日志；不要默认读取全部日志。

## 写入规则

- 完成实质任务后，写一篇 日志/YYYY-MM-DD-任务标题.md，记录目标、决策、检查范围、文件变更、验证、结果和遗留问题。
- 只有会影响未来工作的结论才进入 当前状态/、决策/ 或知识/。
- 用户已明确确认的长期约定可以写入 active 页面；不确定的内容只能写入日志的“待确认长期记忆”。
- 新结论替代旧结论时，更新 active 页面，并将旧决策标记为 superseded 或 deprecated，不要删除历史。
- 长期页面和日志使用 YAML frontmatter，至少包含 type、status、kind、importance、updated、topic。

## 固定操作

- 记忆同步：写日志，提出长期记忆候选，并刷新日志索引。
- 记忆检索 <关键词>：先查 MOC 和当前状态，再按需查知识页与历史日志。
- 记忆体检：运行 python wiki_memory/工具/memory_lint.py check，报告缺字段、断链、重复 active 主题和孤儿页面。
- 记忆压缩：将重复历史归纳到当前状态或知识页，不删除原始日志。

## Git 约定

每次完整对话完成一组连贯的仓库修改后：先审核 diff 并运行相关验证，再提交并推送到配置的远程仓库。不得提交或推送未完成、失败或无关的修改；推送失败时保留本地提交并报告原因。

## 边界

不要批量删除历史、覆盖 active 决策、复制私密信息或把本地课堂转写样本加入仓库，除非用户明确授权。
