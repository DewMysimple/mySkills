# 减少记忆重复调用与验证

## 目标与结果

用户反馈业务任务已完成却反复验证记忆、已建记忆仍频繁调用 Skill，明确要求整改。3.2.1 禁用隐式调用；日常直接遵循项目协议，只有明确记忆管理请求才加载 Skill。新建接入、协议模板、参考及本仓库既有协议同步；本机安装为仓库符号链接，未批量修改其他真实工程。

## 关键变化

- 同一上下文复用未变的已读内容，日常只同步受影响页面，复用业务验证；不为记忆复核全库或重跑历史测试。
- 导航变化或项目要求时统一 index --apply；记忆变化或项目要求时普通 check 一次；无变化的普通 / 只读任务不检查。
- 严格验收限初始化、迁移、模式 / Schema 升级或明确完整验收，替代普通 check；迁移计划和维护者回归不作为日常收尾。
- 相同文件状态通过即停；error 如实处理或报告，warning 不阻断、不循环清零。保持 standard 内容合同、来源、历史及本仓库提交推送规则。

## 实际验证与范围

Windows / PowerShell / Python 3.14.2，main，基线 ffc6a33 加本任务变更；PDF 既有修改保留，未纳入本任务。

- 整改前 33 页普通 check 0.297 秒、index 只读预览 0.113 秒，含 Python 启动。结果支持优先修复流程重复，不能外推大型工程耗时。

- YAML 实读确认源包与本机符号链接的 allow_implicit_invocation 均为 false；项目定制、moc_defaults 和其他 Skill 策略保留。

## 限制与后续

脚本速度只在当前仓库测量；小案例不保证所有模型与工程表现。其他工程协议为独立副本，更新 Skill 不会自动重写；按授权仅调整日常调用与频率条款，不需重新初始化或重验历史。具体 Git 交付结果以本任务最终回复和提交历史为准。
