# 解除转录重复确认门禁

## 诊断与修改

- 起点为 `main` 的 `db396c9`。该版 `SKILL.md` 第 46 行有固定分流及委派确认措辞，`batch-review.md` 第 20 至 27 行要求配对角色和整批写入，长文与回填分别耦合角色或全批预检。
- 历史桌面轨迹证实，实际触发「确认执行」的是用户级安装副本 `SKILL.md` 第 27 行。当次工具审批策略为 `never`。桌面同版本 app server 以 `skills/list` 强制重新发现时仍列出这个安装副本。隔离探针也验证了同进程缓存可继续返回旧描述，强制重载后更新。
- 入口改为清晰任务直接处理，普通整理默认新建，明确要求替换时才启用替换模式。按文件复核与保存，保留映射、双审查、长文覆盖及回填的字节核验。写入前先审查临时候选，使用目标已存在即失败的方式发布新文件。设计依据见 [ADR-005](../../决策/ADR-005-转录调度与逐文件写入.md)。

## 验证

- Desktop CLI `0.166.0-alpha.6` 与 `gpt-5.6-sol` medium 用相同请求及三份合成输入复现。用户级副本预检后要求再次确认，产出 0 份。隔离项目中的整改副本直接写入 3 份，正文首行无空行，源哈希保持。两次轨迹记录了发现及实际读取的路径。
- 实测中间版把同名目标误判为已授权替换。进一步复现了 `apply_patch` 的 `Add File` 会改写已有目标，因此入口明确新建方式和暂存用途。Windows 下 16 组两路并发的拒绝覆盖移动均只有一路成功，且保留了预检后出现的目标。
- 最终版用 Codex CLI `0.144.6`、同模型和推理设置、禁用原生多代理执行四项合成文件任务。空目录保存 10 份，单一既有目标冲突保存 9 份，重复映射保存 1 份独立稿，显式全有或全无遇冲突时保存 0 份。源及既有目标哈希一致。三次发布均在暂存复核之后使用拒绝覆盖的文件移动，无额外确认。
- 定时冲突测试在预检和暂存之后注入新目标。发布检测到冲突后隔离该项，另两份结果继续保存，注入目标保持原字节。
- 独立的 Desktop CLI 回填写入两个授权目标，保留 BOM、CRLF 和 frontmatter 前缀，批准正文除前导分隔外逐字节一致。缺少闭合边界的目标及所有批准稿保持原样。
- 40 行长稿按最多 7 行读取，在 Desktop CLI 单 Agent 路径及当前会话的原生子代理中分别完成。外部核对覆盖账本、接缝、术语、源稿哈希、YAML、代码和标记。CLI 的原生调用缺少线程上下文，原生执行证据来自当前会话的实际派发。
- 最终版在 `gpt-5.6-sol` medium 的隔离只读运行中生成 27 份编辑候选，通用 13 组和实践 14 组均通过逐项保真与可读性复核。`quick_validate.py` 及 `python -X utf8 -B -m unittest discover -s video-transcript-polisher/tests -v` 通过，后者为 11 项字面检查器单测。

## 使用范围

本次交付为仓库版本。用户级安装副本的哈希保持原样。同步整个 Skill 后新建会话，核对发现路径、实际读取轨迹和文件指纹。合成素材、运行轨迹与课程资料留在各自工作范围。
