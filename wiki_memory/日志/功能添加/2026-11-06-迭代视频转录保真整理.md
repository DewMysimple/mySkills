# 迭代视频转录保真整理

## 目标与变更

- 按用户确定的「编辑转录文本」原则，区分基础修复、局部润色与结构、知识性重写。保真和阅读体验分别复核。批处理仍以整文件分工，正式写入受原复核门槛约束。
- 长篇由同一编辑者通读有序窗口，使用术语和主题表及源范围账本，汇合后查覆盖、顺序、衔接和源身份。字面检查工具只提供异常线索。
- 补充 13 组合成正反例和复用指南，同步中文使用说明、界面提示及相关记忆。

## 实际验证与范围

Windows PowerShell、Python 3.14.2，`main` 基线 `fb72226960483cb7973ef4e9e48725ddb3e22765` 加本任务变更。起始已有 PDF Skill 改动与本地提示词。

- `quick_validate.py video-transcript-polisher` 通过。核对条件引用、界面 YAML 与 13 条样例结构。运行 `python -X utf8 -B -m unittest discover -s video-transcript-polisher/tests -v`，11 项通过。检查器在 13 个正例中未发现所支持的字面差异，定位了两个改动字面标记的反例。
- Codex CLI 0.144.6、`gpt-5.6-sol`、固定只读权限，用独立临时会话比较旧版和最终版的三份相同合成输入。CLI 的工作区写入尝试受工具权限限制，内容对照从最终回复收集 Markdown。中间版本提前改写被讲者回指的原话，也漏掉适合导航的主题结构。收紧措辞保护与结构判据后复跑，最终保留原说法和后续澄清、限制和推测，技术样例有两个有原文依据的标题和三步列表，并清理更多填充词。两版的带锚点样例均保留元数据、代码和说话人轮次。
- 另以独立 Agent 对 43 行合成转录执行每次至多 10 行的窗口读取、五段编辑与默认 `processed/lecture.md` 写入。逐段复核后，源文件 SHA-256 保持，写入与组装稿逐字节一致，时间戳、数字、代码、元数据及最后一段完整。
