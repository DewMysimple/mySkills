# 按真实样本修复转录可读性

## 诊断与实现

- 只读按序词元对齐确认 12 对课程稿。按空行分段从 398 减至 185，12 份处理稿均无标题和列表。前 10 对的三个明确语法故障仍在，T8–T10 有明确且持续展开的转场。字面统计只衡量变动幅度。24 份文件的内容哈希复核一致。
- 当次本机安装副本与仓库基线不同。已安装规则要求首行留空，且没有明确一级标题时略去生成的二级标题。旧处理稿的首行空白与此一致。缺少历史会话调用轨迹，无法确认加载版本，也无法把过度保守单独归因于模型或批处理。
- 主流程先定位确定可修的句段和有原文依据的主题边界，再复查机会是否落实。对已放弃且无独立信息的起句保留邻近完整意思，歧义词段逐字保留。保真复查拒绝补写缺失成分、将观察改成要求或猜测界面指代。同步中英文入口和 14 组去身份化用例，沿用既有 13 组、字面检查器及长文、批处理和回填协议。

## 实际验证

Windows PowerShell、Python 3.14.2。仓库 `main` 从 `63cdc66cf4989ff9c02ea79a6b5d1c3215893699` 起步，PDF 变更和本地提示词为已有工作。

- `python -X utf8 -B -m unittest discover -s video-transcript-polisher/tests -v` 退出 0，11 项通过。Skill 的 `quick_validate.py`、界面 YAML、引用、27 条样例结构和正例字面检查通过。E9 数字反例触发提示。语义判断来自逐项对照。
- Codex CLI 0.144.6，`gpt-5.6-sol`，medium，`-a never exec -s read-only --ephemeral --ignore-user-config`。每例独立目录，直接读取固定路径和哈希的 Skill 与输入，禁用安装副本的自动加载，`-o` 收集正文。仓库基线与最终版共 28 次退出 0，输入均保持。按保真、可读性分别评审，基线通过 12/14，E4 补出人员需求，E6 自行解释分组。中间版本曾补义、重排歧义词或保留已确认的残片。最终版 14/14 通过。E1–E3 和 S1–S5 在两版的短样例中均通过。另将已安装规则固定为第三组，S1、S3 均复现零标题和首行空白。
- 最终版抽测三个通用用例，元数据与代码、回指澄清、段落合并均通过。独立 Agent 用早期候选的同一文件路由与参考协议，在临时目录验证三个文件场景。两稿复核后批量写入，其中一稿以至多八行的读取窗口覆盖全部 26 行，源稿哈希和 YAML、时间戳、说话人、代码保持。一个回填目标的 YAML 边界损坏时整批停止。有效回填的 BOM、CRLF 前缀和批准正文通过字节比对。
