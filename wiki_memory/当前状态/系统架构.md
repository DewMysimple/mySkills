# 系统架构

## 模块职责与边界

| 路径 | 职责 |
| --- | --- |
| `video-transcript-polisher/` | 精简指令入口，批处理复核和批准稿回填按需读取参考 |
| `pdf-book-to-obsidian/` | 转换协议、参考规范、提取及维护脚本、隔离测试 |
| `wiki-memory/` | 可复用的工程记忆 Skill、协议模板、模型说明、可选理论原文、六类真实目录示例和初始化工具 |
| `wiki_memory/` | 本仓库的五页当前状态、Skill 专题、决策、日志和工具副本 |

## 数据流与依赖

- 每个 Skill 通过自己的 `SKILL.md` 独立发现；`agents/openai.yaml` 提供界面元数据。维护一个 Skill 不默认修改另外两个。
- 记忆读取路径：根指令 → `wiki_memory/AGENTS.md` 与 `wiki_memory/README.md` → 三份必读状态 → 当前任务相关专题。README 合并说明与导航，目录索引用工具生成，手写事实留在生成区外。
- `wiki_memory/工具/memory.py` 是 `wiki-memory/scripts/memory.py` 的独立副本，配置 schema 为 `2`；3.1.0 增加标准日志分类约束，副本升级和实际验证见本轮日志，其他项目不会自动变化。配置的 `moc_defaults` 保留新目录页所需的 `kind`、`importance`。
- standard 的日志按 `kind` 进入六分类目录，空目录用 `.gitkeep` 保存；单一 `日志/MOC_工作日志.md` 递归收录。Skill 资产中的虚构日志仅演示布局，不成为项目真实历史；`references/llm-wiki.md` 原文是可选理论背景。
- 原记忆的模块 / 流程 / 规范 / 运维分类、模板、历史决策和三篇旧日志保留；原 `memory_lint.py` 留作历史工具，日常索引与体检统一用 `memory.py`。

## 运行与部署

- 仓库交付物是 Skill 能力包；本轮未配置统一应用服务或部署流水线。
- 记忆工具要求 Python 3.10+，只用标准库。当前实际验证环境是 Windows、PowerShell、Python 3.14.2；其他环境需另行验证。
- 本机 `wiki-memory` 通过个人 Skills 目录中的符号链接指向本仓库；此安装属于本机环境，克隆仓库不会自动复现。
