# 系统架构

## 模块职责与边界

| 路径 | 职责 |
| --- | --- |
| `video-transcript-polisher/` | 保真编辑入口、按需长篇分段与批处理及回填、可选字面差异检查、合成回归样例 |
| `pdf-book-to-obsidian/` | 转换协议、参考规范、提取及维护脚本、隔离测试 |
| `wiki-memory/` | 可复用的工程记忆 Skill、协议模板、模型说明、可选理论原文、六类目录示例、初始化/迁移规划工具和隔离换会话评测 |
| `wiki_memory/` | 本仓库的五页当前状态、Skill 专题、决策、日志和工具副本 |

## 数据流与依赖

- 每个 Skill 通过自己的 `SKILL.md` 独立发现；`agents/openai.yaml` 提供界面元数据及调用策略。wiki-memory 自 3.2.1 禁止隐式调用，日常直接用项目协议；其他 Skill 的策略未改。
- 记忆读取从根指令、协议与 README 开始。只读窄查询按需定位；修改或接续先读概览、约束和待办。README 链接到当前状态与各目录索引，自动区使用相对 Markdown 链接，手写事实留在生成区外。
- `wiki_memory/工具/memory.py` 是独立副本，当前 3.4.0、schema 2。专项复核用 `impact` 匹配 Git 路径与页面来源，升级可用 `tool-diff` 比较本地工具与基准。日常检查频率沿用项目协议，`moc_defaults` 定制保留。
- standard 的日志按 `kind` 进入六分类目录，空目录用 `.gitkeep` 保存；单一 `日志/MOC_工作日志.md` 递归收录。Skill 资产中的虚构日志仅演示布局，不成为项目真实历史；`references/llm-wiki.md` 原文是可选理论背景。
- 原记忆的模块 / 流程 / 规范 / 运维分类、模板、历史决策和三篇旧日志保留；原 `memory_lint.py` 留作历史工具，日常索引与体检统一用 `memory.py`。

## 运行与部署

- 仓库交付物是 Skill 能力包；本轮未配置统一应用服务或部署流水线。
- 记忆工具要求 Python 3.10+，只用标准库。当前实际验证环境是 Windows、PowerShell、Python 3.14.2；其他环境需另行验证。
- 本机 `wiki-memory` 通过个人 Skills 目录中的符号链接指向本仓库；此安装属于本机环境，克隆仓库不会自动复现。
