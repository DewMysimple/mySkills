# Skill 更新流程

## 一句话结论

Skill 更新应先读当前文件和工程记忆，再按 skill-creator 规范做最小修改，验证后同步日志并提交推送。

## 流程

1. 检查 Git 状态和目标 Skill 当前结构。
2. 从 wiki_memory/入口.md 读取项目概览、全局约束、当前待办，再按任务定位模块专题；读取 skill-creator/SKILL.md。
3. 只保留影响模型决策的规则；模式专属内容放入按需参考。
4. 以 UTF-8 模式运行 quick_validate.py（Windows 示例：`python -X utf8 ...`）和必要的人工结构检查。
5. 更新受影响的当前状态、决策或知识页，写一篇实质任务日志，运行 `python -X utf8 wiki_memory/工具/memory.py index --project . --apply` 与 `check --project .`。
6. 审核 diff，提交并推送本次完整对话产生的连贯修改。

## 常见陷阱

- 不要因为一个案例就把所有边界条件堆进核心入口。
- 不要把普通任务的确认门、子代理账本或回填细节写成全局必经流程。
- 不要把历史日志当作当前架构事实。
