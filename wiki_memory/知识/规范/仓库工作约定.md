# 仓库工作约定

## 一句话结论

每次工程完成一组连贯的对话修改后，必须先验证和审核 diff，再执行 Git 提交并推送。

## 适用范围

适用于一次完整对话实际修改了 mySkills 仓库文件的情况。只读检查、未完成的中间状态、失败的实验和无关本地修改不应被提交或推送。

## 执行要求

- 先确认修改范围，保留与本任务无关的现有变更。
- 运行适用的 Skill 校验、项目 `memory.py` 体检和人工 diff 审查；具体入口以根 `AGENTS.md` 为准。
- 提交信息应描述本次完整修改的主要交付物。
- 推送到配置的远程分支；若认证、网络或远程状态导致推送失败，保留本地提交并报告，不伪造完成状态。

## 来源

- 用户在本轮对话中明确确认该约定。
