# 标准日志分类与理论溯源

## 选择与依据

决策者：用户，2026-10-09。原模板的日志目录实际具有六类文件夹，但旧文字规则仍写平铺路径，迁移为 Skill 时没有落实目录分类。

- standard 必须保留 `功能添加`、`UI修改`、`Bug处理`、`工程讨论`、`测试验证`、`工程维护` 六目录，日志按主要 `kind` 对应归档；lite 允许平铺。
- Skill 主入口保留关键要求和按需资源链接；分类细节、迁移说明及真实目录样例分放在参考、协议与资产中，不把全部分类理论塞进主入口。
- 原 `llm-wiki.md` 原样保留为可选背景参考，记录用户提供的本地来源和 SHA256。原文作者及上游 URL 未核实，不推定归属；理论原文不扩大工程记忆的操作范围，也不作为每轮 Agent 必读材料。

## 实施与验收

初始化建立六目录，使用 `.gitkeep` 保留空目录，不复制虚构示例为真实历史。已有 standard 日志按现有 kind 移动并修复引用，保留事件日期、当时命令和结论；单一工作日志 MOC 递归收录。

配置仍为 schema 2，工具/协议升级至 3.1.0。新版本标准记忆、交付检查与索引写入校验分类目录及 kind 一致性；旧版本普通 check 保留只读迁移提示。实现和验证证据见本次任务日志，决策页本身不证明测试通过。
